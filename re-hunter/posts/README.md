# الطلبات والعروض

## تقسيم ملفات المصدر

- `html/posts.html`: هيكل الصفحة وحقولها، مع Tailwind utilities ذات البادئة `tw-`.
- `scss/posts.scss`: مدخل التنسيقات. `_screen.scss` للصفحة، و`_cards.scss` للكروت. التخطيط المعتاد يستخدم Tailwind عبر `@apply`، وتبقى تجاوزات الثيم القديم داخل SCSS.
- `ts/model.ts`: الفلاتر وتصنيف أصحاب المنشورات.
- `ts/render.ts`: رسم النتائج والعدادات والترتيب.
- `ts/screen.ts`: الفلاتر المختارة والتصفير.
- `ts/cards.ts`: عرض الكارت.
- `ts/controller.ts`: أحداث الصفحة وتهيئتها مرة واحدة.
- `ts/actions.ts`: إجراءات الكارت المستخدم في الصفحة وبعض الأقسام الأخرى.
- `ts/comments.ts`: واجهة تعليقات المنشور ووظائفها الحالية.
- `ts/export.ts`: تصدير النتائج.
- `ts/types.ts`: أنواع بيانات الصفحة.
- `ts/legacy.d.ts`: حدود الربط المؤقتة بخدمات ومحرك التطبيق القديم.
- `ts/index.ts`: واجهة الصفحة العامة `AQMPostsPage`.

## التشغيل والتعديل

`runtime/` ملفات توافق للمتصفح وElectron، لأنهما لا يشغّلان TypeScript أو SCSS مباشرة. عدّل ملفات المصدر أعلاه. النسخة الحالية تحتفظ بتنسيق الصفحة أثناء الانتقال.

من مجلد `alaa-deals-app`:

```powershell
npm run build:posts
npm run sync
```

أو للمراقبة وإعادة التجميع والمزامنة أثناء التعديل:

```powershell
npm run dev:posts
```

`npm run sync` ينسخ الملفات فقط ولا يشغّل التجميع. إعداد Tailwind محلي للصفحة، بدون Preflight، لحماية بقية التطبيق من تغيير التنسيقات. نستخدم Tailwind 3 مع Sass في هذه المرحلة.

عند النقل لفريم ورك، يتحول `html/` إلى templates/components، و`scss/` إلى styles، و`ts/` إلى logic/services. استبدل حدود الربط في `legacy.d.ts` بخدمات محقونة. دوال الرسم الحالية تتعامل مع DOM مباشرة، ولا تعتمد على فريم ورك بعينه. `dashboard.js` يحتفظ بالمحرك والخدمات المشتركة ويطلب رسم الصفحة عبر `AQMPostsPage`.
