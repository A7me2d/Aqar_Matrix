# تحديثات Aqar Matrix

المصدر: https://github.com/A7me2d/Aqar_Matrix/releases

زر الهيدر موجود في Angular ولوحة التحكم الأصلية. الفحص يحصل عند فتح الصفحة،
وعند عودة الاتصال، وكل خمس دقائق طالما الصفحة ظاهرة. الضغط على «لا يوجد تحديث»
يعيد طلب الفحص (السيرفر يحتفظ بالنتيجة خمس دقائق لتقليل طلبات GitHub).

- «لا يوجد تحديث»: لا يوجد إصدار مستقر أعلى من النسخة الحالية، أو لم ينشر أول Release بعد.
- «يوجد تحديث الآن»: يوجد إصدار أعلى ومعه ملف التثبيت المكتمل، والضغط يبدأ تنزيله.
- داخل نسخة Setup يظهر شريط التحميل والنسبة، ثم التحقق وحفظ البيانات والتثبيت وإعادة فتح البرنامج تلقائيًا.
- «الإصدار قيد التجهيز»: يوجد Release أعلى لكن ملف تثبيته غير متاح بعد.
- «تعذّر فحص التحديث»: خطأ اتصال أو GitHub، والضغط يعيد المحاولة.

زر الهيدر مخفي أثناء الفحص وفي حالة عدم وجود تحديث، ويظهر فقط عند توافر
تحديث أو أثناء تنزيله وتثبيته، أو لإعادة محاولة تحديث فشل. الفحص في الخلفية
مستمر حتى لو كان الزر مخفيًا.

يُقارن رقم الإصدار رقميًا بثلاثة أجزاء، مثل `10.80.63`، وتُستبعد Drafts
وPrereleases. تحديث الكود على main وحده لا يمثل إصدارًا جديدًا.

## نشر إصدار جديد

1. من فولدر `alaa-deals-app` ارفع رقم الإصدار، مثل:

   ```powershell
   npm version patch --no-git-tag-version
   ```

2. احفظ التغييرات وملفي package.json وpackage-lock.json في commit، ثم ارفع
   main والتاج المطابق لرقم الإصدار:

   ```powershell
   git push origin main
   git tag v10.80.63
   git push origin v10.80.63
   ```

   الرقم هنا مثال، ويجب أن يطابق `alaa-deals-app/package.json` بالضبط.

3. Workflow `Publish Windows release` يُجهّز صفحات المشروع وواجهة Angular
   ويُخرج مثبت Windows x64 والنسخة المحمولة، ثم ينشرهما في GitHub Release
   مع `latest.yml` وملفات `.blockmap`. انتظر نجاحه في تبويب Actions.

يمكن إعادة النشر من Actions ثم Run workflow بإدخال تاج موجود. لن ينشر
الـWorkflow رقمًا مختلفًا عن package.json. لا تضف PAT إلى كود التطبيق؛ النشر
يستخدم GITHUB_TOKEN الخاص بالـWorkflow فقط، والتحميل عام.

## الملفات المطلوبة لو رفعت الإصدار يدويًا

ارفع مع Release مستقر يحمل Tag مثل `v10.80.63`:

- `AqarMatrix-Setup-10.80.63.exe`، وهذا هو الملف الذي ينزله زر الهيدر.
- `AqarMatrix-Portable-10.80.63.exe` إن أردت توفير النسخة المحمولة.
- `latest.yml` وملفات `.blockmap` من نفس عملية التغليف لتوافق electron-updater.

لا تستخدم Source code ZIP بدل ملف التثبيت، ولا ترفع مثبتًا قديمًا تحت رقم جديد.

## سلوك التنزيل

داخل نسخة Setup المثبّتة على ويندوز يستخدم `desktop-updates.js` حزمة
electron-updater لتنزيل التحديث إلى الكاش والتحقق من سلامته ببيانات `latest.yml`.
النسبة تصل للهيدر عبر حدث `app:release-state`، ثم تُحفظ البيانات ويُستدعى
`quitAndInstall(true, true)` لتثبيت النسخة وإعادة تشغيلها. الفشل لا يغلق التطبيق،
والضغط على الزر يعيد المحاولة. الفحص الدوري لا يستبدل حالة تنزيل جارٍ، والضغط
المتكرر لا يبدأ تنزيلات متوازية.

في النسخة المحمولة أو وضع تطوير السورس، تنزيل Setup يدوي ويذهب إلى
`Downloads/AlaaDealsExt/exports`. في المتصفح يدير مدير التنزيلات تحميل الملف على
جهاز المستخدم، ولا يتم تثبيت شيء على جهاز السيرفر البعيد. ملفات Windows
تعمل على Windows x64؛ فتح اللوحة من موبايل لا يجعل المثبت تطبيق Android.

التثبيت وإعادة التشغيل التلقائيان خاصان بنسخة Setup، ولا يتم إغلاق متصفح
المستخدم أو تثبيت شيء على السيرفر من زر متصفح بعيد. بيانات المستخدم تبقى
في فولدر التطبيق المعتاد، ولا تُستبدل بملفات الإصدار. النسخ الأقدم من هذه
الميزة تحتاج تثبيت الإصدار الذي يحتويها مرة واحدة بالطريقة اليدوية.

بعد تعديل كود Electron أو remote.js أثناء التطوير، أعد تشغيل Electron حتى
تُحمّل واجهة `/api/updates` الجديدة، ثم حدّث صفحة Angular. إعادة تحميل
المتصفح وحدها لا تعيد تشغيل سيرفر Electron.

## واجهة النسخة المثبتة

الإصدارات التي تحتوي `app/engine/angular/index.html` تفتح Angular تلقائيًا.
البرنامج يشغّل خادمًا خاصًا على `127.0.0.1` وبورت متاح يختاره النظام، مع
رمز دخول مؤقت وكوكي HttpOnly. هذا مستقل عن إعداد سيرفر الموبايل والشبكة،
ولا يحتاج تشغيل ng serve أو فتح البورت 4200 أو تفعيل سيرفر الشبكة.

المحرك القديم يظل داخل iframe في الواجهة الجديدة، وتُمرَّر له واجهات Electron
الحالية من الـpreload عبر إطار من نفس المصدر، مع بقاء واجهة المتصفح العادية
تستخدم web-shim. أوامر فتح الأقسام وواجهة الموبايل تستهدف إطار المحرك نفسه.

على سيرفر الشبكة، `/d/` يوجه إلى `/d/angular/index.html` عند وجود ملفات Angular.
يظل `/d/dashboard.html` متاحًا للمحرك وللتوافق مع الإصدارات القديمة. تشغيل السورس
بدون ملفات Angular المجمّعة يستخدم لوحة التحكم القديمة، ويمكن تطوير Angular
بالأمر `npm run dev:ui` كالمعتاد.
